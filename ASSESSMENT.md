# Planetary assessments

Birth sessions calculate and cache assessments once. Chat and language changes reuse the session. Install `requirements.txt` to enable the pinned PyJHora 4.8.7 engine (AGPL-3.0-or-later). Attribution: https://github.com/naturalstupid/PyJHora.

Shadbala includes Sthana, Kala, Dig, Cheshta, Naisargika and Drik for seven classical planets. Results show virupas and rupas (60 virupas per rupa). The calculation uses Lahiri, mean nodes, local historical timezone offset and Moshier positions. All nine planetary positions must agree with the displayed chart within 0.01 degrees. Dig uses library method 2. Epoch-table Cheshta uses circular averaging and shortest angular distance; Sun/Moon Cheshta is zero under this convention. Threshold ratios are not assigned because conventions differ.

Ashtakavarga includes eight BAV rows (seven planets plus ascendant), SAV excluding the ascendant row, contributor tables, Trikona and Ekadhipatya reductions, and Rasi/Graha/Shodhya Pindas. Nodes do not contribute. Pindas use explicit planetary ordering. The unreduced seven BAV totals sum to 337.

All 284 D1 yoga rules in the pinned catalogue are attempted. Each records present, absent or not evaluated. This is a defined catalogue, not every yoga in every tradition. Rule descriptions are shown without promised benefits.

The local corpus supplies research excerpts from Brihat Jataka with chunk IDs, source IDs and locators. OCR excerpts remain unreviewed unless already approved. No approval metadata is changed; unreviewed passages are not used as consumer interpretation evidence. Empty searches are not evidence that a rule is absent from the book.

Assessment runs offline, with elevation lookup disabled. Tests check positional agreement, complete components, bounded angles, point totals, reduction/pinda consistency and status coverage. These checks do not independently validate the strength engine, all yoga definitions, high-latitude sunrise behavior or historical conventions. Strength totals and yoga matches are not marriage dates or wealth probabilities.

Hindi uses stored numerical facts and fixed prose, avoiding free-form model translation. It is a simple chart summary, not a literal translation of an English model answer. Unsupported translation retains the original with a notice.
